# Android 模拟器 ARM64 小红书安装失败分析

## 核心内容

在 Apple Silicon Mac 上尝试用 Android Studio AVD（ARM64 模拟器）安装小红书 APK，遭遇 `INSTALL_FAILED_NO_MATCHING_ABIS` 错误，最终确认此路线技术上不可行。

## 关键点

- 小红书官方 APK（v9.19.4）只包含 `armeabi-v7a`（32位）架构
- ARM64 模拟器（Android 9+）**彻底去掉了 32 位兼容层**（houdini/libhoudini）
- x86_64 模拟器虽然兼容 32 位，但无法在 Apple Silicon 上运行（QEMU 架构不匹配）
- Android 9 之前的版本可能有 32 位兼容层，但 Google APIs 镜像不含；需要找含 houdini 的第三方镜像（BlueStacks / LDPlayer 等，但这些在 macOS 上不可用）

## 已安装环境（备存）

| 工具 | 路径 / 状态 |
|------|------------|
| Android Studio | `/Applications/Android Studio.app` |
| SDK 根目录 | `~/Library/Android/sdk/` |
| platform-tools (adb) | 已安装，PATH 已配置 |
| uiautomator2 (Python) | 已安装 |
| AVD: Pixel6_ARM64 | Android 15 / ARM64 / Google APIs |
| AVD: Pixel6_PlayStore | Android 14 / ARM64 / Google Play Store |
| AVD: Pixel9_Android9 | Android 9 / ARM64 |

## 为什么重要 / 关联

- 这是探索小红书自动化路线的技术死路记录，避免将来重复踩坑
- 结论：**MAC 本地方案走 rednote.app（Accessibility API），不走 Android 模拟器**
- 关联决策：xhs-mac-mcp 构想
