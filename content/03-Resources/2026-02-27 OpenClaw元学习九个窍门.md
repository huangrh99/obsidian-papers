# OpenClaw 元学习的九个窍门

## 核心问题

OpenClaw 在同一对话里能干，但对话结束就忘——下次启动几乎是白纸。尽管有核心记忆 + 每日记忆机制，它不知道什么该记、什么该忘、什么时候更新。

**元学习**：让 agent 把错误、成功和发现，持续写回到自己的运行文件，改变以后每次启动的行为。和 RAG 不同——RAG 是"告诉它去哪找"，元学习是"让它下次直接换做法"。

**三个层次**：
1. 出了问题就修、写规则防着
2. 发现规律，弄清楚为什么这类事总出问题
3. 系统自己改进自己，连学习方式本身也在变

---

## 九个窍门

### 一：出了事就立刻写进「别再犯」清单

每次出明显问题，在核心 memory 文件里加一行，每次启动都读：

```
Regressions（不要重蹈覆辙）
- [日期] 出了什么事 → 以后怎么做
```

> 每行十几个 token，但能永久防住一类问题。

### 二：记忆分档 + 标注可信度

| 档位 | 内容 | 更新频率 |
|------|------|---------|
| 法典级 | 安全规则、硬约束、身份定义 | 永不过期 |
| 策略级 | 当前项目、整体方向 | 每季度刷新 |
| 临时级 | 当前 bug、变通方案、任务上下文 | 30天归档 |

每条记忆带标注：
```
[可信度:0.9 | 来源:直接告知 | 最后使用:2026-02-22 | 命中次数:12] 用户喜欢命令行部署
```

可信度打分：Boss 直接说 = 1.0，观察推断 = 0.7，未验证外部信息 = 0.5。
新旧矛盾时：旧的归档而不是删除（知道它曾经被推翻过）。

### 三：做决定前先写预测结果

```
日期 — 决策内容
预测：预期结果是什么
不确定的地方：哪里可能出问题
把握：高/中/低
实际结果：（事后填）
和预期不一样的地方：（事后填）
以后要调整的判断：（事后填）
```

关键在「和预期不一样的地方」——发现系统性偏差（总是低估迁移麻烦/总是对新工具过于乐观）。

### 四：每晚自动跑「今天学到了什么」

定时任务，三件事：
1. 检查今天的决定和推理有没有书面记录
2. 更新被用到的记忆条目的命中计数
3. 测试：如果明天是新 session，只看文件能不能还原今天发生了什么？不能就补写

### 五：遇到前后矛盾的指令，记下来别默默执行

设「矛盾日志」，遇到冲突不自己解决，记下来在合适时机让人拍板。
防止两条规则叠在一起导致行为诡异但没人知道为什么。

### 六：设置有过期时间的「临时关注点」

```
临时关注：xxx
内容：xxx
设置时间：yyyy-mm-dd
过期时间：yyyy-mm-dd
解除条件：xxx
```

过期后主动续期，而不是一直挂着变成噪音。

### 七：对自己说出来的话，标注它的性质

公认事实 / 我自己观察到的 / 我推断的 / 我猜的 / 我故意唱反调的。
这个动作本身就是干预——强迫从「复述模式」切换到「思考模式」。

### 八：创意和策略类工作单独设规则

- 至少提出一个让自己也觉得有点冒险的角度
- 先说一遍大家的共识是什么，再说为什么你不同意
- 宁可选「有意思但可能错」，不选「绝对稳妥但无聊」

只在创意/策略任务时生效，日常执行不带这些。

### 九：自我迭代要有结构，不能无限「再改改」

流程：生成 → 按具体标准评估 → 找出差在哪 → 只改那个差的地方 → 重复。
**连续三轮改进幅度不到 5% 就停下来。**

---

## 三个最容易犯的错误

1. **把 RAG 当成学习**：规则只在检索时找到 ≠ 每次启动都内化了
2. **只优化这次对话，不管下次**：调 prompt 是让今天更好，元学习是让以后每次更好
3. **建了回路但没有闭合**：写日记但没人读；预测写了结果从没填；矛盾记下来从没讨论

## 上手顺序

1. 先做窍门一（立刻生效）
2. 一周后：窍门二（清理过时上下文噪音）
3. 一个月后：窍门三（看到校准规律）
4. 跑稳了再加：窍门四（自动提炼任务）
5. 基础稳了再做：7/8/9（认知质量类）
