## 背景

xhs-mcp 评论回复功能存在多个 bug，Boss 通过 iMessage 指挥调试。

## 核心修复：子评论回复

**问题**：`reply_comment_in_feed` 对子评论失败——子评论无 `id` 属性，DOM 查找返回 null。

**修复路径**（多轮调试）：
1. `findSubComment`：改用 `reply-container-first-child` 策略（在父评论回复容器中找第一个有内容的子评论）✅
2. 回复按钮点击：JS 标记按钮 → 获取坐标 → `page.Mouse.MoveTo + Mouse.Click`（不能用 rod `Element.Click()`，会卡在 Interactable 检查）✅
3. 输入内容：`page.InsertText(content)`（不能用 `element.Input()`，依赖 element 引用）✅
4. 提交按钮：同样用坐标点击 ✅

**核心教训**：XHS headless 浏览器场景下，所有交互必须用坐标鼠标事件，element 引用的 `Click()` 会卡死在 Interactable 检查上。

## 登录状态误报问题

**症状**：巡逻报 `is_logged_in: false`，但 cookies 仍有效
**根本原因**：server 重启后 browser 实例重新初始化需要时间，期间 API 返回 false
**修复方案**：遇到 false 先重启 server 再重试，不要直接要求用户扫码
