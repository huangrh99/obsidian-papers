# 层级记忆架构落地

## 核心内容

今日完成 JARVIS 记忆系统从"单文件堆叠"到"三层索引架构"的重构，解决 MEMORY.md 随时间膨胀的 token 消耗问题。

## 三层结构

| 层级 | 文件 | 注入时机 | 目标大小 |
|------|------|---------|---------|
| **L0 索引** | `MEMORY.md` | 每次会话自动注入 | ≤1000字 / ~300 tokens |
| **L1 细节** | `memory/*.md`（非日期） | 按需 `read` | 无限制 |
| **L2 日志** | `memory/YYYY-MM-DD*.md` | 按需 `read` | 原始日志 |

## L1 细节文件

- `memory/profile.md` — Boss 信息 & 频道
- `memory/tools.md` — 路径 & API keys
- `memory/xhs.md` — 小红书运营
- `memory/projects.md` — 项目记录

## Token 节省效果

| | 旧方案 | 新方案 |
|--|--------|--------|
| MEMORY.md 注入 | ~900 tokens（持续增长） | **~272 tokens（固定）** |
| 6 个月后预估 | 3000-5000 tokens | **仍然 ~300 tokens** |

## 关键规则

- 启动时只读 MEMORY.md（L0）
- 需要细节时根据索引按需 read 对应 L1 文件
- 新决策前置信息 → 更新 MEMORY.md
- 新执行细节 → 更新对应 L1 文件
- 日常事件 → 写入 memory/YYYY-MM-DD.md
- L0 严格控制 ≤1000字，超了把细节下沉 L1

## 同步修改的文件

- `MEMORY.md` — 重写为索引层
- `AGENTS.md` — 记忆章节改为层级架构说明
- `TOOLS.md` — 去掉冗余模板文字

## 为什么重要

解决了 AI 助手长期使用后"记忆文件变大 → 每次注入 token 变多 → 响应越来越慢且贵"的根本问题。L0 永远保持小而精，细节按需加载。
