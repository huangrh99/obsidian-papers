# xhs 删除评论 UI 方案调试与结论

## 背景

有 4 条多余顶级评论需要删除（测试残留）：
- `699eaef4` - "哈哈对的！私信那边..."
- `699e6eee` - "哈哈被你发现了..."
- `699eb67e` - "哈哈对的！私信那边..."（重复）
- `699bebfe` - "对了补充一句..."

## 调试过程

### 尝试 1：Go HTTP client 直接调用删除 API
- API 路径：`/api/sns/web/v1/comment/delete`（不是 /remove）
- 结果：**-104 风控**

### 尝试 2：headless 浏览器 UI 点击三点菜单
- 问题：`.delete-dropdown` (16×17px SVG) 坐标 `(1184.6, 373.0)`
- 实际点击到用户头像/昵称，弹出 hover card 而非菜单
- 根因：headless 未登录状态，cookies 未生效于新建 browser 实例

### 尝试 3：rod 新建 browser + SetCookies
- cookies 文件：`/tmp/cookies.json`（有效，含 `web_session`）
- 结果：XHS UI 层仍显示未登录（headless 指纹检测）
- 点击三点菜单触发**登录弹窗**而非删除下拉

### 尝试 4：JS Vue 内部调用 deleteComment
- 无法从 DOM 外部访问 Vue 实例私有方法

### 尝试 5：XHR 同源请求（代替 fetch）
- 在 xhs-mcp server 已登录 page 上下文里执行 XHR
- 结果：**仍然 -104**
- 结论：风控是 headless fingerprint 级别，不是 CORS/认证问题

## 最终结论

> **-104 风控的核心是 headless fingerprint，与请求方式无关。**
> 只有真实 Chrome 浏览器里发出的请求才能通过。

## 可行方案

1. **Browser Relay（真实 Chrome）** ← 最快，但需要 Boss attach tab
2. **等 xhs-mcp 上游更新** — 官方加删除功能后签名机制可能不同
3. **Anti-fingerprint headless 研究** — 成本高，暂不值得
